# Development and verification

## Environment

Use Node 22.12+ and `npm ci`. Copy `.env.example` to `.env.local`, then run `npm run dev` and open `http://localhost:3000`. A consistent hostname is required by OAuth/cookie/origin checks. `BETTER_AUTH_URL` must include the port when changing it.

The embedded database is a single-process local option. Stop the app before running an independent import or migration process against that PGlite directory. For external PostgreSQL, multiple app connections are supported. Migrations are explicit in production, automatically applied in local embedded mode. Import/migration commands read `.env.local` and respect already-exported environment variables.

For optional PostgreSQL in Docker:

```sh
export POSTGRES_PASSWORD='choose-a-local-development-password'
docker compose up -d
```

Set `DATABASE_URL=postgres://cuantai:YOUR_PASSWORD@localhost:5432/cuantai` in `.env.local`, run `npm run db:migrate`, then restart the app. Percent-encode special URL characters in credentials. Docker configuration is provided but was not executed in this session.

## Quality workflow

```sh
npm run format
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
npm audit --omit=dev
```

`vitest.config.mts` selects deterministic domain/provider/input tests. `playwright.config.ts` selects browser/API integration tests. Local E2E reuses a running server when available; otherwise it starts the dev server with a test PGlite path. Unique `.test` accounts isolate test data. Authentication limits stay enabled; account setup honors `X-Retry-After`.

Never run two app processes against the same PGlite directory. A production preview should use a separate directory and canonical port. External PostgreSQL is the required path for concurrent production instances.

Keep development and production build commands sequential: they share the generated `.next` directory. If local generated types contain duplicate copies such as `routes.d 2.ts`, stop the app, move `.next` outside the repository, and rerun `npm run check` to regenerate it. These files are build artifacts; do not suppress application type errors or move persistent `.data` records. `next-env.d.ts` is also generated by Next.js and ignored by Git.

## Research calculation conventions

- SMA: arithmetic rolling mean; first value appears only after the full period.
- EMA: seeded by SMA over the first period, then alpha = 2/(period+1).
- RSI: Wilder-smoothed gains/losses; flat series = 50, no losses = 100, no gains = 0.
- MACD: default EMA 12 minus EMA 26, signal EMA 9; slow period editable.
- Bollinger: rolling SMA ± two population standard deviations.
- ATR: true ranges after the first close, Wilder smoothing.
- OBV: starts at zero; volume signed by close-to-close change.
- VWAP: volume-weighted typical price, resets at UTC-session boundaries; disabled on daily or longer intervals. Exchange-specific session calendars are pending.
- Trend compares EMA 20 and EMA 50; equal averages within relative floating-point tolerance are neutral.
- Technical levels: minimum low and maximum high of the last twenty candles. They are rolling historical extremes, not predictive or confirmed support/resistance.

These functions support deterministic research. They no longer render the chart or feed chart prices. TradingView now provides all price-chart rendering/data and its own indicators/tools. New saved workspaces contain opening settings only; legacy definitions remain readable for instrument/interval/style recovery. The widget owns its streams and drawing tools. See [integration and tests](TRADINGVIEW.md).

## AI boundary

The asset overview and conversation architecture, calculations and API contract are described in [Asset intelligence](ASSET_INTELLIGENCE.md). Apply migration `0003_asset_chat.sql` before serving private chats on external PostgreSQL. Local PGlite applies it at process startup. Restart an existing dev process after adding migrations.

`report.ts` is browser-safe deterministic report logic. `analysis.ts` is server-side orchestration. Collection retrieves normalized market data, optional fundamentals and dated headlines. The model must call `get_asset_evidence`; final prose is parsed using a Zod schema. Source IDs are allowlisted; digits in generated prose are rejected, keeping numerical values in deterministic metric cards. This reduces unsupported numerical claims but does not prove semantic factuality. Fundamental, macro and event information stays unavailable when it was not retrieved.

The current bounded research request uses at most two model requests, output-token caps, timeouts and a daily per-user request budget. No external AI call was made without configured credentials. Narrative generation, Google OAuth and real email delivery remain externally unverified.
